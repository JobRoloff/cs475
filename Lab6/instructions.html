CS475 Lab 6: Profiling CUDA Programs with Nsight Systems

Introduction

The purpose of this exercise is for you to learn how to use NVIDIA Nsight Systems (nsys) to see where a CUDA program spends its time: running kernels on the GPU, copying data between CPU and GPU memory, waiting in CUDA calls, or working on the CPU.

You are given a program that multiplies two N x N matrices of floats, C = A * B, with a simple kernel in which every thread reads a whole row of A and a whole column of B from global memory. You will write a tiled version of the kernel that uses shared memory, profile both programs with nsys, and answer the questions at the end of this page.

Resources that may be useful for this assignment include:

  • The Nsight Systems 2024.6 User Guide, the version installed on the lab machines. See the command line profiling section.
  • NVTX documentation
  • Documentation for gnu make
  • The Shared Memory section of the NVIDIA CUDA C++ Programming Guide for CUDA 12.8, which works through a matrix multiply with and without shared memory.

The GPUs are shared. Before you time or profile anything, run nvidia-smi and use a machine whose GPU shows 0% utilization and no running processes; another user's job on the same GPU will distort your times.

Load the CUDA module (CUDA 12.8, the default version). This also gives you nsys:

Download and untar the CUDAL6.tar file. To compile a CUDA program, use the CUDA compiler nvcc. The provided Makefile builds sgemm00. Add rules to it to build sgemm01 from your sgemmKernel01.cu, the same way sgemm00 is built from sgemmKernel00.cu.

Matrix multiply: tiling with shared memory

sgemm.cu multiplies two N x N matrices. It launches (N/16) x (N/16) thread blocks of 16 x 16 threads (BLOCK_SIZE in sgemmKernel.h), and each thread computes one element of C. In the provided kernel, sgemmKernel00.cu, each thread reads a whole row of A and a whole column of B from global memory, so every element of A and B is read from global memory N times.

For this lab you must create a new kernel called sgemmKernel01.cu, with the same MatMulKernel function, that uses tiling. The thread block works through A and B one BLOCK_SIZE x BLOCK_SIZE tile at a time. In each step, every thread loads one element of a tile of A and one element of a tile of B into shared memory, the block waits with __syncthreads(), and then every thread adds up its part of the product from shared memory. Each element loaded from global memory is then used BLOCK_SIZE times. N must be a multiple of BLOCK_SIZE, so you do not need to handle partial tiles. Do not change sgemm.cu or sgemmKernel.h.

sgemm.cu checks a sample of C against a computation on the CPU and prints Test PASSED or Test FAILED. Make sure your kernel passes.

Here is a set of files provided in CUDAL6.tar:

  • Makefile
  • sgemm.cu
  • sgemmKernel.h
  • sgemmKernel00.cu
  • timer.h
  • timer.cu

Run both programs with N = 4096 (./sgemm00 4096 and ./sgemm01 4096) and note the time each one prints.

Profiling with Nsight Systems

nsys runs your program and records a timeline of what it does on the CPU and the GPU. Profile each program: 

nsys profile -o sgemm00 ./sgemm00 4096
nsys profile -o sgemm01 ./sgemm01 4096
Each command runs the program and writes a report file (sgemm00.nsys-rep, sgemm01.nsys-rep). To profile again into an existing report file, add --force-overwrite true.

Print summary tables from a report with nsys stats: 

nsys stats --report nvtx_sum,cuda_api_sum,cuda_gpu_kern_sum,cuda_gpu_mem_time_sum,cuda_gpu_mem_size_sum sgemm00.nsys-rep
All times in these tables are in nanoseconds.
  • nvtx_sum: the phases of the program. sgemm.cu marks its phases (initializing A and B, copying them to the GPU, the warm-up and timed kernels, copying C back, and checking C) with NVTX ranges, using nvtxRangePush and nvtxRangePop.
  • cuda_api_sum: time the CPU spends in each CUDA call.
  • cuda_gpu_kern_sum: time each kernel runs on the GPU.
  • cuda_gpu_mem_time_sum and cuda_gpu_mem_size_sum: time taken and amount of data for the copies between CPU and GPU memory.

If you are working at a lab machine, you can also open a report in the Nsight Systems GUI with nsys-ui sgemm00.nsys-rep and look at the timeline: the CUDA HW row shows when kernels and copies run on the GPU, and the NVTX row shows the phases of the program. The GUI is optional; you can answer the questions from the nsys stats tables.

Questions

  1. From cuda_gpu_kern_sum, what is the average time of MatMulKernel in sgemm00 and in sgemm01, and what is the speedup of your tiled kernel? Why are there two instances of the kernel, and do the times agree with the times the programs print?
  2. From cuda_gpu_mem_time_sum and cuda_gpu_mem_size_sum, how much data is copied to the GPU and back, how long do the copies take, and what transfer rate (GB/s) do they reach? How does the total copy time compare with one run of your tiled kernel?
  3. In cuda_api_sum, cudaLaunchKernel takes only microseconds, but cudaDeviceSynchronize takes about as long as the kernel. Why? One of the three cudaMalloc calls is also much slower than the other two. Which one, and why? (Hint: it is the first CUDA call in the program.)
  4. From nvtx_sum, which phase of sgemm01 takes the most time, and does it run on the CPU or the GPU? If you made your kernel twice as fast, about how much faster would the whole program run?
